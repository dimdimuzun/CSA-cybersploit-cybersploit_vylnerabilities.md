# Мапінг проходження CTF "Empire Breakout" на OWASP Top 10 (2021)

Важливе зауваження: OWASP Top 10 створений для вразливостей **веб-застосунків**, тому не всі кроки CTF (наприклад, network reverse shell, privilege escalation через Linux capabilities) сюди природно лягають — це радше системні/OS-рівневі вразливості, які виходять за межі OWASP. Але ось відповідність там, де вона є, плюс пояснення, де OWASP не застосовний.

| Крок CTF | Категорія OWASP Top 10 (2021) | Пояснення |
|---|---|---|
| Дефолтна сторінка Apache + каталог `manual` доступний | **A05:2021 – Security Misconfiguration** | Дефолтна документація/сторінки веб-сервера не були прибрані після встановлення — класичний приклад misconfiguration. |
| `dirb` знаходить приховані директорії | **A05:2021 – Security Misconfiguration** | Відсутність контролю доступу до службових/дефолтних директорій дозволяє їх виявити брутфорсом. |
| Пароль у HTML-коментарі (Brainfuck-encoded) | **A02:2021 – Cryptographic Failures** | Кодування (Brainfuck) — це **не шифрування**, а обфускація. Зберігання креденшлів у клієнтському коді, навіть "закодованих", є грубим порушенням захисту чутливих даних. |
| Пароль у HTML-коментарі (сам факт витоку) | **A01:2021 – Broken Access Control** (частково) | Чутлива інформація опинилась у публічно доступному коді сторінки — по суті, відсутність розмежування, що має бути видимим клієнту. |
| Usermin — панель адміністрування, доступна ззовні на порту 20000 | **A05:2021 – Security Misconfiguration** | Адміністративна панель з широкими правами виставлена в мережу без обмеження доступу (IP allowlist, VPN тощо). |
| Вхід у Usermin з валідними обліковими даними без MFA | **A07:2021 – Identification and Authentication Failures** | Відсутність багатофакторної автентифікації та, ймовірно, слабка політика паролів дозволили просте використання скомпрометованих креденшлів. |
| Веб-термінал у Usermin, доступний авторизованому користувачу | **A01:2021 – Broken Access Control** | Користувач "cyber" має доступ до функціоналу (веб-shell), який фактично дає йому надлишкові привілеї в системі — порушення принципу найменших привілеїв. |
| SUID/capabilities (`cap_dac_read_search`) дозволяють обхід прав доступу | **A01:2021 – Broken Access Control** | Хоча це на рівні ОС, а не застосунку, логіка та сама: неправильно налаштовані права дозволяють обійти контроль доступу до файлів. |
| Backup-файл `.old_pass.bak` з паролем у відкритому вигляді | **A02:2021 – Cryptographic Failures** | Зберігання паролів у відкритому текстовому вигляді, навіть у backup, є прямим порушенням захисту чутливих даних. |
| Backup-файл доступний через exploit (`tar`) попри обмеження прав | **A05:2021 – Security Misconfiguration** | Некоректні права доступу до backup-директорії / файлу дозволили непризначеному користувачу дістатись даних. |

## Категорії OWASP, що НЕ застосовні до цього CTF
Ці кроки виходять за межі веб-рівня і належать радше до OS Hardening / CIS Benchmarks, а не OWASP:
- Reverse shell через Python (мережева експлуатація, не веб-вразливість застосунку)
- `enum4linux`, `nmap` (мережева розвідка — ближче до NIST/MITRE, ніж до OWASP)
- `su root`, privilege escalation через Linux capabilities (рівень ОС)

## Підсумкова діаграма покриття

```
A01 Broken Access Control        → 3 епізоди (веб-shell, capabilities, коментар з паролем)
A02 Cryptographic Failures       → 2 епізоди (Brainfuck-кодування, plaintext backup-пароль)
A05 Security Misconfiguration    → 4 епізоди (Apache manual, dirb, Usermin exposure, backup perms)
A07 Auth Failures                → 1 епізод (відсутність MFA/слабкий контроль автентифікації)
```
