# CTF Cheat Sheet — Crypto / Forensics / Pwn (з нуля)

Друга частина шпаргалки команди. На відміну від першої (яка виросла з ваших реальних проходжень), тут бази практичного досвіду не було, тому документ побудований інакше: спершу коротке пояснення концепції, потім — що робити руками. Мета не зробити з команди експертів за два тижні, а дати достатньо, щоб впізнати тип завдання і знати перший крок.

**Як цим користуватись:** прочитайте розділ цілком хоча б раз перед тренуванням, а на самому змаганні — тільки блоки з командами.

## CRYPTO

### Три речі, які часто плутають

- **Кодування** (encoding) — не секрет, оборотне без ключа. Base64, hex, URL-encoding. Будь-хто може розкодувати, маючи сам закодований текст.
- **Шифрування** (encryption) — оборотне, але потребує ключа/пароля. AES, RSA, класичні шифри (Цезар, Віженер).
- **Хешування** (hashing) — **необоротне**. MD5, SHA1, SHA256. Хеш не можна "розшифрувати" назад — пароль підбирають, порівнюючи хеші кандидатів (брутфорс/словник), а не декодують.

Перший крок у Crypto-завданні завжди один: **визначити, з чим із трьох маєш справу**, а вже потім діяти.

### Швидке впізнавання за виглядом рядка

| Виглядає як | Найімовірніше | Що робити |
|---|---|---|
| Літери+цифри, закінчується на `=` або `==` | Base64 | `echo "STR" \| base64 -d` |
| Тільки `0-9a-f`, довжина парна | Hex | `echo "STR" \| xxd -r -p` |
| `%XX` послідовності | URL-encoding | CyberChef → URL Decode |
| 32 hex-символи | MD5-хеш | hashid → john/hashcat |
| 40 hex-символів | SHA1-хеш | hashid → john/hashcat |
| 64 hex-символи | SHA256-хеш | hashid → john/hashcat |
| Тільки `.` та `+` або `-` з цифрами | Brainfuck (код) або Morse | CyberChef / dcode.fr |
| Текст, де частота букв схожа на звичайну мову, але літери зсунуті | Класичний шифр (Цезар/Атбаш/Віженер) | CyberChef "Magic" або брутфорс зсуву |
| Довгі числа через кому/пробіл | Можливо RSA-параметри (n, e, c) або ASCII-коди | Перевірити на RSA-таск або декодувати як ASCII |
| Base64, а після декодування — незрозумілі байти | Подвійне кодування або стиснений/бінарний файл | `file` одразу після декодування |

**Золоте правило**: перш ніж брутфорсити щось незрозуміле, **спробуй визначити формат**. CyberChef "Magic wand" часто вгадує сам.

### Класичні шифри (підстановочні)

- **Цезар (Caesar)**: кожна літера зсунута на N позицій. Усього 25 варіантів зсуву — можна перебрати вручну або через CyberChef "ROT13 Brute Force".
- **Атбаш (Atbash)**: перша літера алфавіту заміняється на останню, друга на передостанню тощо. Без ключа, фіксована заміна.
- **Віженер (Vigenère)**: Цезар, але зсув змінюється по ключовому слову. Складніше зламати без ключа — шукати підказку поруч із шифротекстом.
- Якщо шифротекст схожий на звичайний текст, але "зламаний" — перевірити всі три вище через CyberChef, перш ніж вигадувати щось екзотичне.

### Кодування, з якими стикаєтесь найчастіше

```sh
# Base64
echo "STR" | base64 -d

# Hex
echo "48656c6c6f" | xxd -r -p

# URL-encoding — через CyberChef, рідко є зручна CLI-команда

# Base32 / Base58 / Base85 — немає стандартної утиліти в Linux
# Base32:
echo "STR" | base32 -d
# Base58/Base85 — CyberChef офлайн, або python:
python3 -c "import base58; print(base58.b58decode('STR'))"
```

Якщо після декодування вийшла "каша" — спробуйте декодувати ще раз (подвійне кодування) або перевірте тип файлу: `file output`.

### Хеші: впізнати й зламати

Хеш не розшифровують — його **підбирають**. Процес завжди такий:
1. Визначити тип хешу.
2. Обрати інструмент і словник (або режим брутфорсу).
3. Чекати.

```sh
# Крок 1: визначити тип
hashid hash.txt

# Крок 2a: словникова атака (швидше, якщо пароль "звичайний")
hashcat -m 0 -a 0 -D 1 hash.txt /usr/share/wordlists/rockyou.txt   # -m 0 = MD5
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt

# Крок 2b: брутфорс по масці (якщо знаєш структуру пароля — довжину, символи)
hashcat -m 0 -a 3 -D 1 hash.txt ?a?a?a?a?a?a --increment
```

Основні номери типів хешу для `-m` у hashcat: `0` = MD5, `100` = SHA1, `1400` = SHA256, `1000` = NTLM. `hashid` сам підкаже правильний номер.

### RSA (базові атаки для CTF)

RSA — асиметричне шифрування (публічний і приватний ключ). У CTF майже завжди йдеться не про "зламати RSA математично", а про **погану реалізацію**. Типові завдання дають `n`, `e`, `c` (а іноді й більше) і просять відновити повідомлення.

Перше, що варто спробувати — автоматичний інструмент:
```sh
git clone https://github.com/Ryan1729/RsaCtfTool  # або встановлена версія
python3 RsaCtfTool.py --publickey key.pub --uncipherfile ciphertext
```
Він сам перебирає десяток типових слабкостей: мале `n` (факторизується), спільний модуль з іншим завданням, малий показник `e` без padding, відомі прості числа в базах (factordb.com).

Якщо інструменту немає — вручну перевірити `n` на [factordb.com]: якщо число вже розкладене кимось раніше, весь приватний ключ відновлюється за кілька секунд.

### XOR

Часто зустрічається як "простий" шифр у Misc/Crypto. Два варіанти:
- **Single-byte XOR**: весь текст пошифрований одним байтом-ключем (0-255 варіантів) — перебрати всі, шукати читабельний результат.
- **Repeating-key XOR**: ключ — коротке слово, що повторюється. Складніше, але CyberChef має рецепт "XOR Brute Force" для коротких ключів.

```python
# Швидкий brute-force для single-byte XOR
data = bytes.fromhex("...")
for key in range(256):
    result = bytes(b ^ key for b in data)
    if all(32 <= c < 127 for c in result):  # виглядає як друкований текст
        print(key, result)
```

### Інструменти, які варто мати офлайн

- **CyberChef** (офлайн-збірка) — універсальний швейцарський ніж для кодувань і класичних шифрів
- **RsaCtfTool** — автоматичні атаки на RSA
- **hashid**, **hashcat**, **john**
- **openssl** — часто вже є в системі, корисний для перевірки сертифікатів, швидкого хешування
- Python з бібліотеками `pycryptodome`, `base58`

## FORENSICS

Forensics — про те, щоб знайти інформацію у файлі, образі диска, дампі пам'яті чи мережевому трафіку, яку автор завдання навмисно заховав, видалив або замаскував.

### Перший крок завжди однаковий: подивитись, що це за файл

```sh
file suspicious_file          # визначає тип файлу за сигнатурою, не за розширенням
exiftool suspicious_file      # метадані: автор, дата, GPS-координати, інколи прямий текст
strings suspicious_file | less   # всі друковані рядки у файлі — швидкий спосіб знайти флаг напряму
```

Не нехтуйте `strings` — у половині легких forensics-завдань флаг просто лежить відкритим текстом усередині бінарного файлу.

### Приховані/вбудовані дані у файлах

```sh
binwalk suspicious.jpg          # шукає сигнатури інших файлів усередині (zip, ще один jpg тощо)
binwalk -e suspicious.jpg       # і одразу розпаковує знайдене

foremost -i disk.img -o output/   # carving: витягує файли з образу диска за сигнатурами
scalpel disk.img                  # аналог foremost, інша конфігурація
```

`binwalk` і `foremost`/`scalpel` вирішують різні задачі: `binwalk` шукає "файл у файлі" (типово для зображень з доданими даними), carving-інструменти відновлюють файли з необробленого диска чи дампу, де файлова система пошкоджена або видалена.

### Стеганографія (коротко, детальніше — у першій частині шпаргалки)

```sh
steghide extract -sf image.jpg         # потрібен пароль/ключове слово
stegcracker image.jpg /usr/share/wordlists/rockyou.txt  # якщо пароля немає — підбір
zsteg image.png                        # специфічно для PNG, працює без пароля на базові LSB-техніки
```

### Образи дисків

```sh
# Подивитись структуру образу
fdisk -l disk.img
mmls disk.img          # з пакету sleuthkit — показує розділи

# Змонтувати (для read-only аналізу)
sudo mount -o ro,loop disk.img /mnt/evidence
```

Для серйозного аналізу образу (не одного файлу, а цілого диска) використовують **Autopsy** (GUI, на базі sleuthkit) — підходить, якщо завдання дає `.img`/`.dd`/`.E01` файл і треба знайти видалені файли, переглянути файлову систему, історію браузера тощо.

### Пам'ять (memory dump)

Якщо завдання дає файл типу `memory.dmp` чи `.vmem` — це дамп оперативної пам'яті, аналізується через **Volatility**:

```sh
# Спершу визначити профіль ОС (для Volatility 2)
volatility -f memory.dmp imageinfo

# Список процесів
volatility -f memory.dmp --profile=<profile> pslist

# Список відкритих/недавно використаних файлів
volatility -f memory.dmp --profile=<profile> filescan

# Витягнути конкретний процес чи файл
volatility -f memory.dmp --profile=<profile> procdump -p <PID> -D output/
```

Volatility 3 працює дещо інакше (автовизначення профілю, інший синтаксис плагінів) — перевірте, яка версія встановлена, перед змаганням.

### Мережевий трафік (pcap)

```sh
wireshark capture.pcap     # GUI, найзручніший спосіб досліджувати вручну
tshark -r capture.pcap     # CLI-версія, для скриптів і швидкого фільтрування
```

У Wireshark корисні прийоми:
- **Follow → TCP Stream** (правий клік на пакеті) — складає весь діалог одного з'єднання в читабельний вигляд, часто там і лежить флаг чи креди.
- **File → Export Objects → HTTP** — автоматично витягує всі файли, що передавались по HTTP у цьому captures.
- Фільтр `http.request` — показати лише HTTP-запити, щоб швидко побачити, які URL відвідувались.

### Документи (PDF, Office)

```sh
exiftool document.pdf          # метадані
pdf-parser document.pdf        # структура PDF: об'єкти, потоки, вбудовані скрипти
oletools/olevba document.docx  # аналіз макросів у Office-файлах
```

### Логи

Якщо дають лог-файл (auth.log, access.log тощо) — шукайте аномалії: незвичні IP, багаторазові невдалі спроби логіну (brute-force слід), нетипові User-Agent, часові мітки поза робочим часом. `grep`, `awk`, `sort | uniq -c` — ваші основні інструменти, екзотика рідко потрібна.

### Інструменти, які варто мати офлайн

- `exiftool`, `binwalk`, `foremost`/`scalpel`, `steghide`/`stegcracker`/`zsteg`
- `sleuthkit` (mmls, fls) та, якщо є можливість, **Autopsy**
- **Volatility** (2 і/або 3) + довідник плагінів
- **Wireshark**/`tshark`
- `exiftool`, `pdf-parser`, `oletools` для документів

## PWN (бінарна експлуатація)

Це найважча категорія для новачків, тому мета — не навчитись ламати все, а зрозуміти базову механіку й вміти закрити найпростіші завдання (easy-рівня).

### Що взагалі відбувається

Програма, скомпільована з мови типу C, зберігає дані у двох основних місцях: **стек** (stack, для локальних змінних і адрес повернення з функцій) і **купа** (heap, для динамічної пам'яті). Якщо програма неправильно перевіряє розмір вхідних даних, можна записати більше, ніж виділено — і переписати сусідні дані в пам'яті, включно з адресою, куди програма має "повернутись" після виконання функції. Це і є **переповнення буфера** (buffer overflow) — основа більшості простих Pwn-завдань.

### Захисти, які варто розпізнавати

Перед атакою завжди перевіряйте, які захисти ввімкнені — від цього залежить, яка техніка підійде:

```sh
checksec --file=./binary
```

- **NX (No-eXecute)**: стек не можна виконувати як код — не можна просто покласти shellcode на стек і стрибнути туди. Потребує ROP або подібних технік.
- **Canary (stack canary)**: спеціальне значення перед адресою повернення; якщо воно змінилось — програма аварійно завершується, не дозволяючи переповнення спрацювати тихо.
- **PIE (Position Independent Executable)**: адреси в пам'яті рандомізовані при кожному запуску — потрібно спочатку "злити" (leak) реальну адресу.
- **ASLR**: те саме на рівні ОС — рандомізує адреси бібліотек, стеку, купи.

Для найпростіших CTF-завдань (`ret2win`) часто **все це вимкнено навмисно**, щоб завдання було здійсненним без глибоких знань.

### Типовий робочий процес

```sh
file ./binary              # 32 чи 64 біт, тип
checksec --file=./binary   # які захисти ввімкнені
strings ./binary | less    # іноді прямо видно корисні рядки — назви функцій, підказки
objdump -d ./binary | less # дизасемблювати, подивитись функції (шукати цікаві імена: win, flag, secret)
ltrace ./binary            # які бібліотечні функції викликаються під час роботи
```

### Найпростіша техніка: ret2win

Ідея: у програмі вже є функція (напр. `win()`), яка виводить флаг, але вона ніколи не викликається нормальним шляхом. Завдання — переповнити буфер так, щоб адреса повернення вказувала саме на цю функцію.

```python
from pwn import *

elf = ELF('./binary')
p = process('./binary')  # або remote('host', port) для змагання

win_addr = elf.symbols['win']

# Треба знати, скільки байт до адреси повернення (offset) —
# визначається через gdb/pwndbg: подати патерн і подивитись, де програма впала
offset = 72  # приклад; реальне число завжди визначається індивідуально

payload = b'A' * offset + p64(win_addr)
p.sendline(payload)
p.interactive()
```

Визначення offset — окремий крок: подається унікальний патерн (`cyclic(200)` у pwntools), програма падає, дивимось у gdb, на яке значення впала адреса повернення, і через `cyclic_find()` дізнаємось точний зсув.

### Format string vulnerabilities

Якщо програма передає ваш ввід напряму у `printf(buf)` замість `printf("%s", buf)` — можна використати специфікатори формату (`%x`, `%p`, `%n`) щоб читати чи навіть записувати довільну пам'ять. Розпізнати: програма поводиться дивно, якщо ввести `%x%x%x%x` замість звичайного тексту (виводить сміттєві hex-значення зі стеку).

### ROP (Return-Oriented Programming) — лише загальна ідея

Коли NX увімкнено, виконати власний shellcode напряму не можна. Замість цього з наявного коду бінарника чи бібліотек "збирають" ланцюжок із маленьких шматочків коду (gadgets), що закінчуються на `ret`, і комбінують їх для виконання потрібних дій (наприклад, виклику `system("/bin/sh")`). Це складна тема — для старту досить знати, що вона існує і коли потрібна (NX увімкнено, немає зручної функції типу `win()`).

### Інструменти

```sh
gdb ./binary              # дебагер; з розширенням pwndbg або GEF набагато зручніше
pwndbg-gdbinit             # встановлення pwndbg (одноразово)
checksec --file=./binary
objdump -d ./binary
python3 -c "from pwn import *"   # pwntools — основна бібліотека для написання exploit-скриптів
```

pwntools значно спрощує написання експлойтів: `p64()`/`p32()` для пакування адрес, `cyclic()` для патернів, `ELF()` для читання символів бінарника, `process()`/`remote()` для з'єднання.
