# ica1

В цьому документі наведено розгорнуте пояснення до завдання **Capture the Flag (CTF)**, опубліковане на сайті [**VulnHub**](https://www.vulnhub.com/entry/ica-1,748/) автором **"onurturali"**.
Відповідно до наданої автором інформації, рівень складності цього CTF — **ЛЕГКИЙ**, а мета — отримати **root-доступ** до цільової машини та знайти **файли-прапорців**.

Для проходження цього CTF необхідно мати **базові знання команд Linux** та **навички використання інструментів для тестування на проникнення**.
Завантажити оригінал CTF можна [тут](https://download.vulnhub.com/ica/ica1.zip).

> ⚠️ **Примітка**: Для запуску всіх віртуальних машин було використано [**Oracle VirtualBox**](https://www.virtualbox.org/).
> Для проходження CTF використано [**Kali Linux**](https://www.kali.org/docs/introduction/download-official-kali-linux-images/) як атакуючу машину.
> Використані методики призначені **виключно для освітніх цілей**.<br>
> **Відповідальность за їх застосування проти будь-яких інших цілей буде визначатись відповідно чинному законодавству.**

В документі розглянуто віртуальну машину **ICA1** з платформи для тестування на проникнення яка призначена для тренувань, перевірки надійності мережі та налаштування привілеїв.
Завдання є середньої складності з всебічним випробуванням для відточування навичок тестування на проникнення, пропонуючи реальні сценарії та вектори атак.

У цьому завданні моделюється наступний сценарій.
Згідно з отриманою інформацією, **ICA** працює над секретним проектом.
Нам потрібно з'ясувати, що це за проект, отримати інформацію для доступу до системи, встановити бекдор.
Для цього необхідно буде пройти кілька рівнів безпеки.
Розпочнемо ми з аналізу, далі виявимо відкриті порти та доступні сервіси, продовжимо ідентифікувати вразливості і, нарешті, використаємо ці вразливості для отримання root-доступу.
На завершення розглянемо деякі рекомендації для підвищення стійкості та надійності віртуальної машини.

## **Короткий огляд кроків вирішення CTF**
1. Завантажити та запустити цільову машину та інструмент для дослідження.
2. Отримати **IP-адресу цільової машини** за допомогою **netdiscover**.
3. Просканувати **відкриті порти** за допомогою **nmap**.
4. Дослідити **HTTP-сервіс** на 80 порті. Провести огляд файлової системи web серверів та виявити приховані файли та папки.
5. Скачати та дослідити yaml файлу з параметрами доступу до бази даних.
6. Отримати доступ до сервера MySQL та дослідити облікові записи web користувачів.
7. Скопіювати список користувачів та захешованих паролів на комп'ютер Kali.
8. Встановити файл зі списком ключових слів.
9. Проаналізувати захешовані паролі.
10. Розглянути методи декодувння паролів користувачів.
11. Підібрати паролів користувачів travis і dexter.
12. Дослідити профілі користувачів travis і dexter.
13. Виявити шляхи для підвищення привілеїв.
14. Отримати контроль над системою.

### **Крок 2: Отримання IP-адреси цільової машини за допомогою netdiscover**
Після завантаження та запуску цільової віртуальної машини у **VirtualBox** першим кроком визначимо її IP-адресу.
У нашому розпорядженні є кілька інструментів, таких як ```arp-scan```, ```netdiscover``` та ```nmap```.
Серед названих інструментів найпростішою є команда ```netdiscover -i eth0 -r 192.168.2.1/24```, де
параметер **-i** задає мережевий інтерфейс, наприклад, eth0 або wlan0,
а за допомогою ключа **-r** можна вказати діапазон мережі для сканування.
Опції рекомендують використовувати у випадку, якщо команда без параметрів виконується тривалий час.
Отже, виконаємо:

```sh
sudo netdiscover i eth0 -r 192.168.2.0/24
```

📌 **Результат**:
Ми достатньо швидко отримали IP-адресу цільової машини — **192.168.2.5**.<br>
![targetip.png](./ica1/targetip.png)

⚠️ **Примітка**: IP-адреси атакуючої та цільової машин можуть бути іншими залежно від конфігурації вашої мережеі.

### **Крок 3: Сканування відкритих портів та доступних сервісів**
На цьому кроці виявимо доступні в системі сервіси та їх версії.
Використаємо ```nmap``` для сканування отриманої IP-адреси на наявність **відкритих портів** та **запущених сервісів**.
Для цього використовуємо команду з ключами **--top-ports -A -sV -P** для виконання агресивного сканування.
- Саме опція **-A** активує агресивні параметри сканування. Вона виконує комплексне сканування, яке включає:
  - **виявлення ОС**; визначає операційну систему цільового об'єкта;
  - **виявлення версій**; визначає версії служб, що працюють на відкритих портах;
  - **сканування скриптів**; запускає скрипти за замовчуванням для збору додаткової інформації про цільовий об'єкт;
  - **трасування**; відображає шлях, яким пакети досягають цільового об'єкта.<br>
- Аргумент **--top-ports** вказує сканувати лише зазначену кількість найпопулярніших портів з файлу **/usr/share/nmap/nmap-services**.
Це дозволяє пришвидшити сканування, перевіряючи лише найімовірніші відкриті порти замість усіх 65535.
- Опція **-sV** дозволяє визначати версії сервісів на портах.
Виконаємо команду:

```sh
nmap --top-ports 100 -A -sV -P 192.168.2.5
```

📌 **Результат**:
Ми побачили три відкриті порти: 22 для служби SSH, 80 для веб-сервера та 3306 для сервера MySQL.
- **22** порт використовується службою **SSH**;
- **80** порт прослуховується веб-сервером;
- **3306** порт використовується запущеним сервером MySQL.<br>
![targetport.png](./ica1/targetport.png)

### **Крок 9: Аналіз захешованих паролів**
Як відомо, хеш MD5 неможливо "декодувати" (розшифрувати) у початковий текст, оскільки це не шифрування, а одностороння математична функція.
Однак, щоб підібрати пароль, на практиці використовують метод брутфорсу (перебору) або словникову атаку, який дає такий самий хеш.
Для цього у **Kali Linux** використовують вбудовані утиліти **Hashcat** та **John the Ripper**.
Обидві утиліти є проінстальовані в **Kali Linux**.
Параметри утиліт можна дізнатися виконавши їх з ключем ```--help```.<br>
![hashcathelp.png](./ica1/hashcathelp.png)<br>
![johnhelp.png](./ica1/johnhelp.png)

Спочатку ми повинні зрозуміти, які об'єкти ми отримали у файлі **passwords.txt**.
Файл містить список захешованих паролей. Ще раз відобразимо його вміст

```sh
c3VSSkFkR3dMcDhkeTNyRg==
N1p3VjRxdGc0MmNtVVhHWA==
```

Щоб дізнатися, який режим хешу (```-m```) нам потрібен, можна проаналізуйте хеш за допомогою спеціальних утиліт ідентифікації, довідників або online сервісами.

За допомогою параметра ```-m``` передамо одну з наших стрічок у каманду **hashid**.

```sh
hashid -m "c3VSSkFkR3dMcDhkeTNyRg=="
```

Згадаємо стандарти хешування, які використовуються при розробці програмного забезпечення.
Як відомо, хеш MD5 складається з 128 біт, що дорівнює 16 байтам.
Проте для зручності читання та передачі у різних програмних утилітах (зокрема у **Hashcat**), ці 16 байт подають у шістнадцятковій (```Hex```) системі числення, через що токен містить 32 символи.
Тобто, кожен байт записується двома символами у 16-й системі числення (цифри від 0 до 9 та літери від a до f).

Однак, результат хешування за алгоритмом MD5 може також складатися із 22 байтів.
Це відбувається, якщо до результату хешування застосовується кодування **Base64**.
В цьому випадку кожен символ 16-ти байтного токена кодується 6-ма бітами інформації.
Якщо математично розрахувати кількість байт, то отримаємо ```128 : 6 = 21.33```.
Оскільки кількість символів повинна бути цілим числом, то щоб помістити всі біти відбувається заокруглення у більшу сторону.
Так отримуються 22 символи.
У стандартній реалізації  **Base64** (наприклад, згідно зі стандартом ```MIME```) дані заокругляються до найближчого числа, яке кратне до 24 бітів.
Тому, до цих 22-х символів додаються два символи доповнення (padding) ```==```, щоб збільшити довжину рядка до 24 символів.

Отже в базі даних зберігаються захешовані паролі в кодуванні **Base64**.
Щоб скористатися утилітою **Hashcat** або **John the Ripper** нам потрібно спочатку декодувати кожен рядок з **Base64** у вихідний 16-символьний токен, який далі перетворити у HEX формат.
Для цього використаємо утиліту **base64**. За допомогою параметра ```-d``` можна задати як файл, так і окремий токен.
Щоб результат не злився в одну стрічку, використаємо утиліту **fold**. За допомогою параметра ```-w``` вкажемо кількість символів в кожній стрічці.
Щоб зберегти результат виконаємо перенаправлення у файл **passwords_md5.txt**. 

```sh
base64 -d passwords.txt | fold -w 16
base64 -d passwords.txt | fold -w 16 > passwords_md5.txt
cat passwords_md5.txt
```

Переведемо отримані 16-ти байтні токени у 16-ву систему числення.
Одним з найпростіших інструментів для цього є утиліта **xxd**.
Використаємо її з ключем ```-p``` (postscript), який дозволяє виводити значення послідовно, без додаткової службової інформації.
За допомогою ключа ```-c:500``` задамо кілкість колонок, тобто довжину стрічки в парі з ключем ```-p```.
Щоб не видаляти коди переходу на нову стрічку в якості джерела даних використаємо **base64**.

### **Крок 10: Декодування паролів користувачів**
**Hashcat** є одним з найкращих інструментів для відновлення паролів на основі значення хеш функції.
Утиліта підтримує кілька режимів атаки, більше 300-т алгоритмів хешування та вміє використовувати потужності процесора і відеокарти (GPU).

Для коректної роботи **Hashcat** потрібно мати достатній об'єм оперативної пам'яті.
Зокрема, мінімальноий розмір пам'яті для версії ```7.1.2``` становить 4 Gb.
Встановимо у віртуальній машині **Kali Linux** 8 Gb. оператвної пам'яті.<br>
![kalimemory.png](./ica1/kalimemory.png)

Опишемо деякі важливі параметри утиліти **hashcat**.
- Ключ ```-m``` задає тип хешування, зокрема ```-m 0``` вказує на тип хешу MD5. Утиліта **hashid** може нам порекомендувати параметр ключа ```-m```.
- Ключ ```-a``` задає на тип атаки, зокрема ```-a 0``` сигналізує утиліті використовувати словник, a параметр ```-a 3``` вказує на використання режиму брутфорсу з перебором по масці.
- Якщо графічний процесор на нашій машині інтегрований, має малий обсяг відеопам'яті або ми працюємо у віртуальному середовищі, як наприклад в нашій ситуації, то тоді потрібно використовувати системний процесор та оперативну пам'ять замість графічного процесора. Для цьлго будемо використовувати ключ ```-D 1```.

У випадку використання режиму брутфорсу ми можемо задавати маску за допомогою послідовності символів.<br>
![hashcharsets.png](./ica1/hashcharsets.png)

Продемонструємо використання утиліти **hashcat**.
Спочатку підготуємо простий хешкод за алгоритмом MD5, а потім використаємо **hashcat** для відновлення початкового токена.
За допомогою утиліти **md5sum** знайдемо хешкод символів ```aa``` та збережемо результат у файл **simple.txt**.
Використаємо утиліту ```cut``` щоб зберегти у файл лише 32 символи, ігноруючи пробіл та кінцеві символи.

```sh
echo "aa" | md5sum
echo "aa" | md5sum | cut -c 1-32 > simple.txt
cat simple.txt
```

📌 **Результат**:
У файлі **simple.txt** ми отримали 32 символи хеш коду за алгоритмом MD5 токена ```aa``` у 16-й системі числення.<br>

### **Крок 11: Підбір паролів користувачів travis і dexter**
На попередніх кроках ми підготували файл **user.txt** зі списком користувачів та **password_clean.txt** з їхніми захешованими паролями.
Поправимо вміст файлу **user.txt**, переведемо всі символи у нижній регістр.
Для цього скористаємося стандартною утилітою ``sed```. Застосуємо параметри
- Ключ ```-i``` означає виконати заміну в основному файлі.
- Параметр ```s``` вказує на режим заміни після якої в слешах вказуємо що шукаємо і на що замінюємо.
- Шаблон ```.*``` задає перегляд всіх символів, а шаблоном ```\L&``` вказуємо перевести у нижній регістр.

Для контролю будемо виводити вміст файлу **user.txt**.

```sh
cat user.txt
sed -i 's/.*/\L&/' user.txt
cat user.txt
```

Далі ми спробуємо використати отримані імена користувачів та закодовані паролі для здійснення атаки методом перебору на SSH-сервіс який працює на 22 порті.
Для цього використаємо команду **hydra**.
Це вбудований у **Kali Linux** інструмент, який використовується в кібербезпеці та тестуванні для швидкого підбору паролів методом брутфорс (перебору) у реальному часі.
**Hydra** підтримує понад 50 протоколів, включаючи SSH, FTP, HTTP, HTTPS, SMB.<br>

Спробуємо підібрати пароль користувачів **travis** та **dexter**.
Скористаємося наступними параметрами команди **hydra**.<br>
- **hydra** це команда для запуску **hydra**, інструменту для злому паролів методом повного перебору;
- прапорець **-l dexter** вказує ім'я користувача для входу, яке буде використовуватися для атаки повним перебором; в нашому випадку будемо використовувати **travis** та **dexter**;
- за допомогою прапоря **-L user.txt** ми можемо задати файл **user.txt** зі списком користувачів;
- прапорець **-P password_clean.txt** вказує шлях до файлу зі списком паролів, який **hydra** використовуватиме для атаки; ми використаємо **password_clean.txt**;
- параметр **-f** вказує **hydra** зупинитися після першого успішного входу;
- параметр **192.168.2.5** задає цільову IP-адресу для служби SSH;
- параметр **ssh** вказує на протокол, по якому відбуватиметься вхід.

Виконажмо команди для всіх користувачів та **travis** і **dexter** окремо.

```sh

hydra -l travis -P password_clean.txt -f 192.168.2.5 ssh .
hydra -l dexter -P password_clean.txt -f 192.168.2.5 ssh .
```

### **Крок 13: Дослідження потенційних шляхів для підвищення привілеїв**
Вміст файлу **note.txt** підказує нам виконати пошук виконавчих файлів, які потенційно ми можемо використати.
Як відомо, виконавчі файли з встановленим бітом ```setuid``` виконуються з дозволами власника файлу.
Зазвичай це може призвести до ненавмисного підвищення привілеїв, якщо система не була налаштована належним чином.

Скористаємося командою **find** для пошуку файлів, що мають привілеї ```SUID``` та належать користувачу ```root```.
Пошук будемо виконувати всій файловій системі, починаючи з кореневого каталогу ```/```.
Задамо параметр **-type f** щоб шукати файли з встановленим бітом дозволу ```setuid``` **-perm -4000**.
Це зазвичай вказує на те, що такі файли можна виконувати з правами власника файлу.
Щоб отримати детальну інформацію для кожного зі знайдених файлів будемо виконувати команду **ls -al**, а будь-які помилки **2>/dev/null** будуть пригнічуються.

```sh
find / -perm -4000 -type f -exec ls -al {} 2>/dev/null \;
```

📌 **Результат**:
Ми отримали список файлів з встановленим бітом ```setuid``` та власником ```root```.<br>
![findsuidlist.png](./ica1/findsuidlist.png)

Як видно з результатів пошуку, перший файл **/opt/get_access** не є типовим файлом чи каталогом операційної системи.
Тому він привертає увагу. Спробуємо запустити цей файл на виконання.

```sh
/opt/get_access
```

📌 **Результат**:
В результаті виконання ми отримали деяку інформацію.<br>
![optgetaccess.png](./ica1/optgetaccess.png)

Скористаємося командою ```strings``` щоб отримати текстові або символьні послідовності, які вбудовані у бінарний файл.
Ці символьні аослідовності можуть дати уявлення про функціональність або призначення бінарного файлу та виявити жорстко закодовані значення і параметри конфігурації.

```sh
strings /opt/get_access
```

📌 **Результат**:

### **Крок 14: Отримання контролю над системою**
Щоб скористатися виявленою вразливістю створимо власний виконавчи файл **cat**, наприклад, у папці **/tmp**.
Далі створимо командний файл, який буде запускати **bash**.
Виконаємо команди

```sh
echo "/bin/bash" >> /tmp/cat
ls -al /tmp
cat  /tmp/cat
```

📌 **Результат**:
Ми створили командний файл **cat** у папці **/tmp**, який запускає **bash**.<br>
![tmpcatbash.png](./ica1/tmpcatbash.png)

Щоб наш файл **/tmp/cat** можна було виконувати з **/opt/get_access** він повинен бути виконавчим.
Змінимо права доступу до файлу **/tmp/cat**.

```sh
chmod +x /tmp/cat
ls -al /tmp
```

📌 **Результат**:
Файл **/tmp/cat** став виконавчим.<br>
![tmpcatexec.png](./ica1/tmpcatexec.png)

Як відомо, змінна середовища «**PATH** визначає, де оболонка буде шукати виконавчі файли під час введення команди.
Встановимо змінну середовища **PATH** так, щоб файл **/tmp/cat** був першим у списку виконання.
Виконаємо команди

```sh
echo $PATH
export PATH=/tmp:$PATH
echo $PATH
```

📌 **Результат**:
Папка **/tmp** є першою у списку шляхів змінної **PATH**.
Це означає, що при зверненні до системної команди **cat** в дійсності виконається наша команда з папки **/tmp**.
Якщо викликаючий процес буде мати вищі привілеї, то і наша команда теж їх отримає.<br>
![pathcatexec.png](./ica1/pathcatexec.png)

Виконаємо команду **/opt/get_access**.
Для цієї команди встановлений біт ```setuid``` і отже вона працює від імен ```root```.
Оскільки ця команда виконує **cat /root/system_info**, то буде запущено нашу команду **/tmp/cat** з правами ``root```.

```sh
/opt/get_access
ls
```

📌 **Результат**:
Ця команда запустила нову оболонку **bash** з правами **root**.
Ми отримавши доступ до всієї системи та можемо виконувати будь-які дії.
Фактично ми встановлюючи право власності на цю систему.<br>
![rootaccessdone.png](./ica1/rootaccessdone.png)
