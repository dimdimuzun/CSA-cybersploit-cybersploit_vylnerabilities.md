# ffuf vs Gobuster: відмінності та практичне використання

**ffuf і Gobuster** — інструменти для виявлення прихованих ресурсів вебзастосунків: директорій, файлів, віртуальних хостів та інших об'єктів. Обидва використовують словники (*wordlists*), надсилають HTTP-запити й допомагають знаходити ресурси, які не видно під час звичайної навігації сайтом.

**Основна відмінність:** Gobuster має зручні спеціалізовані режими для переліку вебресурсів та імен, а ffuf вирізняється гнучкістю під час fuzzing HTTP-запитів.

## 1. Порівняння можливостей

| Критерій | ffuf | Gobuster |
|---|---|---|
| Основне призначення | HTTP fuzzing | Перебір вебресурсів та імен |
| Пошук директорій і файлів | Так | Так |
| Пошук віртуальних хостів | Так | Так |
| Пошук DNS-піддоменів | Не основний режим | Так |
| Перебір HTTP-параметрів | Гнучкий | Не основне призначення |
| Перебір значень параметрів | Так | Не основне призначення |
| Підстановка значень у HTTP-заголовки | Так | Можливості залежать від режиму |
| Фільтрація результатів | За статусом, розміром, кількістю слів, рядками та іншими критеріями | Є фільтрація, можливості залежать від режиму |
| Складні сценарії fuzzing | Одна з основних переваг | Не основне призначення |
| Простота типового перебору директорій | Висока | Висока |

Обидва інструменти підходять для початкової веброзвідки. Проте **ffuf особливо зручний, коли потрібно не просто знайти URL, а й дослідити реакцію застосунку на різні вхідні дані**.

## 2. Практичні приклади

У прикладах використовується умовна тестова система `http://192.168.56.10`. Виконуйте сканування лише власних систем або за дозволом їхніх власників.

### Сценарій A. Пошук директорій і файлів

**ffuf:**

```bash
ffuf -u http://192.168.56.10/FUZZ \
  -w /usr/share/wordlists/dirb/common.txt
```

Маркер `FUZZ` замінюється кожним словом зі словника.

Пошук файлів із певними розширеннями:

```bash
ffuf -u http://192.168.56.10/FUZZ \
  -w /usr/share/wordlists/dirb/common.txt \
  -e .php,.txt,.html
```

**Gobuster:**

```bash
gobuster dir \
  -u http://192.168.56.10 \
  -w /usr/share/wordlists/dirb/common.txt
```

Пошук файлів із заданими розширеннями:

```bash
gobuster dir \
  -u http://192.168.56.10 \
  -w /usr/share/wordlists/dirb/common.txt \
  -x php,txt,html
```

Обидві команди розв'язують практично однакову задачу. Відрізняються синтаксис і набір параметрів.

### Сценарій B. Фільтрація хибнопозитивних результатів

Припустимо, вебсервер повертає `200 OK` навіть для сторінок, яких не існує. У такому разі самого HTTP-коду недостатньо — потрібно аналізувати розмір або вміст відповіді.

У ffuf можна виключити відповіді певного розміру:

```bash
ffuf -u http://192.168.56.10/FUZZ \
  -w /usr/share/wordlists/dirb/common.txt \
  -mc all -fs 1234
```

Тут `1234` — **умовний розмір відповіді в байтах**, а не універсальне значення. Його потрібно визначити експериментально.

Gobuster також підтримує фільтрацію HTTP-кодів та інші параметри виведення. Однак можливості ffuf щодо фільтрації за розміром, кількістю слів і рядків роблять його особливо зручним для дослідження нестандартної поведінки вебзастосунків.

### Сценарій C. Пошук DNS-піддоменів

Gobuster має спеціалізований режим `dns`:

```bash
gobuster dns \
  -d example.com \
  -w subdomains.txt
```

Інструмент перебирає можливі імена та перевіряє їх розв'язання через DNS.

Для пошуку віртуальних хостів використовується режим `vhost`:

```bash
gobuster vhost \
  -u https://example.com \
  -w vhosts.txt
```

**Важливо розрізняти DNS-піддомени та віртуальні хости.**

- **DNS-піддомен** — ім'я, яке може розв'язуватися через DNS, наприклад `dev.example.com`.
- **Віртуальний хост** — сайт, який вебсервер може обслуговувати за певним ім'ям, переданим, зокрема, через HTTP-заголовок `Host`.

Кілька віртуальних хостів можуть використовувати одну IP-адресу, навіть якщо їхнє DNS-налаштування відрізняється.

### Сценарій D. Fuzzing HTTP-параметрів

У цьому сценарії переваги ffuf проявляються особливо виразно.

Припустимо, ми досліджуємо тестовий вебзастосунок і хочемо з'ясувати, які параметри він приймає:

```bash
ffuf -u 'http://192.168.56.10/?FUZZ=test' \
  -w params.txt
```

Тут ffuf підставляє слова зі словника `params.txt` замість `FUZZ`, перебираючи назви параметрів.

Інший приклад — перебір значень параметра:

```bash
ffuf -u 'http://192.168.56.10/item?id=FUZZ' \
  -w ids.txt
```

У цьому випадку перебираються значення `id`.

ffuf також дозволяє підставляти значення в POST-тіло та HTTP-заголовки, а також використовувати кілька маркерів для різних словників. Це корисно під час дослідження API та складніших сценаріїв тестування.

Gobuster теж має режим `fuzz`, але для складних сценаріїв HTTP fuzzing я б віддав перевагу ffuf.

## 3. Що вибрати для BlackArch і навчальних CTF

Для твоїх завдань — дослідження вразливих віртуальних машин, навчання студентів і розроблення локального AI-асистента з кібербезпеки — я б використовував обидва інструменти, але з різними ролями.

| Завдання | Рекомендований інструмент |
|---|---|
| Первинний пошук директорій і файлів | Gobuster або ffuf |
| Пошук DNS-піддоменів | Gobuster |
| Пошук віртуальних хостів | Gobuster або ffuf |
| Дослідження нестандартних HTTP-відповідей | ffuf |
| Перебір параметрів і значень API | ffuf |
| Автоматизація типових сценаріїв | Обидва, залежно від завдання |
| Навчання початківців | Gobuster для базового переліку ресурсів, потім ffuf |

### Рекомендована послідовність для навчання

**Етап 1. Gobuster — основи переліку ресурсів.**

Студенти вчаться:
- працювати зі словниками;
- знаходити директорії та файли;
- розуміти HTTP-коди відповіді;
- розрізняти доступні ресурси та захищені кінцеві точки.

**Етап 2. ffuf — дослідження поведінки вебзастосунків.**

Студенти опановують:
- перебір HTTP-параметрів;
- аналіз відповідей різного розміру;
- фільтрацію хибнопозитивних результатів;
- дослідження API;
- побудову гіпотез щодо потенційних вразливостей.

**Етап 3. Інтеграція з локальним AI-асистентом.**

Для AI-асистента можна реалізувати такий сценарій:

1. Перевірити доступність вебсервісу.
2. Виконати обмежений перебір директорій за допомогою Gobuster.
3. Зберегти результати в структурованому вигляді.
4. За потреби дослідити знайдені ресурси за допомогою ffuf.
5. Передати результати локальній LLM для пояснення та формування наступних гіпотез.

При цьому AI-асистент має розрізняти **виявлений ресурс і підтверджену вразливість**. Наприклад, наявність `/admin` сама по собі не означає, що доступ до адміністративного інтерфейсу не захищений.

## 4. Підсумкова рекомендація

Якщо коротко:

- **Gobuster** — зручний інструмент для переліку вебресурсів, пошуку DNS-піддоменів і віртуальних хостів.
- **ffuf** — гнучкий інструмент для HTTP fuzzing, перебору параметрів та аналізу реакцій вебзастосунку.
- **Для навчального CTF-середовища варто мати обидва інструменти.**

Для курсу з веббезпеки починаємо Gobuster, а потім переходимо до ffuf, коли є краще розуміння HTTP, словники та принципи аналізу відповідей.
