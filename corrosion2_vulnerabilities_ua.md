
# Вразливості, виявлені під час проходження CTF Corrosion2

Нижче наведено перелік ключових вразливостей, які були знайдені та використані під час компрометації віртуальної машини Corrosion2.

## 1. Відкриті та незахищені порти
- **SSH (22), HTTP (80), Tomcat (8080)** були відкритими без додаткового захисту чи обмежень доступу.
- Це дозволило:
  - досліджувати веб-сервери,
  - отримати доступ до Tomcat Manager,
  - виконувати подальші атаки через доступні інтерфейси.

## 2. Доступний у веб-каталогах файл `backup.zip`
- Файл резервної копії знаходився у відкритому каталозі Tomcat, доступному без автентифікації.
- Дозволив завантажити конфігураційні файли Tomcat, серед яких були **облікові дані admin:melehifokivai**.

## 3. Слабкий пароль архіву `backup.zip`
- Пароль до архіву (
  `@administrator_hi5`
  ) був успішно підібраний через brute-force словником `rockyou.txt`.
- Відсутність достатнього захисту паролем дозволила відкрити конфіденційні файли.

## 4. Збережені у конфігурації Tomcat облікові дані
- Файл `tomcat-users.xml` містив облікові дані адміністратора у відкритому вигляді.
- Відсутність шифрування чи маскування.
- Це дозволило увійти у **Tomcat Manager**.

## 5. Можливість завантаження шкідливих WAR-файлів у Tomcat Manager
- Адміністратор мав право завантажувати `.war` файли.
- Це дозволило розгорнути зворотну оболонку (`revshell.war`).

## 6. Реверсивне з’єднання без захисту
- Сервер прийняв виконання шкідливого коду та підключився назад до атакувальної машини через `netcat`.
- Вразливість: **відсутність обмежень на виконання довільних веб-додатків**.

## 7. Наявність файлів із підказками та прапорцями у домашніх каталогах користувачів
- Користувач `randy` мав файли `note.txt` і `user.txt`, які містили конфіденційні дані та підказки.

## 8. Слабкі паролі користувачів системи
- Паролі зберігались у `/etc/shadow` у вигляді хешів, які були легко зламані через `john` + `rockyou.txt`.
- Пароль `randy`: `07051986randy` — слабкий.

## 9. Небезпечний набір sudo-привілеїв
- Користувач `randy` мав право запускати Python-скрипт `randombase64.py` як root:
  ```
  (root) /usr/bin/python3.8 /home/randy/randombase64.py
  ```
- Скрипт імпортував стандартну бібліотеку `base64`, що дало можливість **замінити бібліотеку** та виконати довільний код від root.

## 10. Неправильні дозволи на системні бібліотеки Python
- Файл `/usr/lib/python3.8/base64.py` був доступний для редагування користувачем.
- Це критична вразливість рівня **Privilege Escalation**.

## 11. Підвищення привілеїв через підміну модуля Python
- Зміна `base64.py` дозволила вставити:
  ```python
  import os
  os.system("/bin/bash")
  ```
- Далі запуск скрипта через sudo дав **root-доступ**.

## 12. Відсутність моніторингу та контролю цілісності системи
- Жодних механізмів, що могли б виявити:
  - зміну системних файлів,
  - завантаження нових веб-додатків,
  - невідомі процеси чи вихідні з’єднання.

# Висновок
Система містила значну кількість вразливостей, серед яких особливо критичними є:
- наявність конфіденційних файлів у відкритих каталогах,
- використання слабких паролів,
- помилки конфігурації Tomcat,
- неправильні sudo-привілеї,
- можливість модифікації системних бібліотек.

Ці вразливості дозволили повністю скомпрометувати систему та отримати root-доступ.
